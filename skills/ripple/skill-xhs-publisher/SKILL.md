# 小红书发布

Ripple 已有统一发布链，**不要为小红书另建第二套账号、审批或回执系统**。

## Ripple 托管流程

1. 准备最终标题、正文、媒体与标签；已有内容版本就直接复用。
2. 用 Ripple 发布草稿能力创建小红书任务，选择对应账号。Agent 返回 `draft` 只表示待审核，未上传、未发布。
3. 用户到「发布管理 → 发布工作台」执行预检并审核当前不可变版本；真实发布授权绑定内容版本和账号授权修订。
4. 工作台确认执行后，Ripple 使用账号专属浏览器 Profile 启动原生发布器。
5. 平台结果分开记录：`published / accepted / unknown_result / verification_required / not_submitted` 等。未知结果先核对，绝不盲目重发。
6. 作品链接经用户/平台核对后写入发布回执；后续作品指标与评论可在「发布记录」「互动管理」读取。

## 与小红书其他能力分工

- 热搜、推荐流、关键词搜索、笔记/账号/评论只读分析 → `skill-xhs-analyzer`
- 生成完整小红书笔记 → `xhs-note-creator`
- 评论回复、顶层评论、删除评论 → `skill-xhs-comment-reply`
- 发布后表现复盘 → `skill-content-postmortem`

这些能力共用 Ripple 的账号 ID、账号隔离 Profile 和业务记录，不重复保存登录态。

## 必要确认

- 草稿创建、预检和分析不等于真实发布，可以直接完成。
- **真实发布**必须在发布工作台对当前内容版本、账号和排期明确确认。
- 内容或媒体在审核后变化，原审批失效，需要重新预检/审核。
- 账号在审核期间重新登录/授权，原审批也失效。
- 已经越过真实提交边界但结果未知时，不因“再点一次”重新发送。

## 数据与隐私

Agent 不读取 Cookie、token、浏览器目录或 xsec 定位参数。发布素材由工作台在执行前做快照，账号状态存在 `.ripple-private`；普通内容/回执只保存脱敏字段。

## 独立 CLI（维护兼容）

只有独立 CLI/维护环境明确具备 Shell 权限时才使用 `skills/shared/scripts/xhs_publish.py` 做检查、登录或发布。它不是 Ripple 托管 Agent 的发布入口，也不应绕过工作台审批用于日常自动发布。

## 完成标准

- “帮我准备发布”完成于发布任务草稿已创建且可在工作台审核。
- “发布到小红书”只有工作台执行并取得可核对状态后才能描述对应结果。
- `accepted`/`unknown_result` 不能说“已经发布”；必须继续核对或由用户确认具体作品链接。
