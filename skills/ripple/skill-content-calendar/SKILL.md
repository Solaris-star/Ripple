# Ripple 内容排期

目标是把已有方向变成一张能直接进入内容工作台的排期。所有事实、热点和既有发布记录都按输入数据处理；缺失信息要写成假设，不能自行补成“已验证事实”。

## 输入优先级

1. 用户明确指定的平台、时间范围、发布频率和业务节点。
2. 当前账号 Profile 与已确认的内容策略。
3. Ripple 内容日历中的已发、待发和活动节点。需要时读取：

```bash
python skills/shared/scripts/calendar_ops.py context --days 45
```

4. 选题池和当前热点，只用于填充尚未确定的档期。
5. 如果以上信息仍不足，提出最少量澄清问题；用户允许快速规划时，采用保守假设并标记。

## 排期规则

- 先锁定有硬日期的发布、合作、节日和活动，再安排常规内容。
- 同一平台连续内容避免主题、形式和转化目标完全重复。
- 高制作成本内容要预留制作时间，不把多个重任务堆在同一天。
- 跨平台复用时记录“母内容 + 平台版本”，不要把相同文案机械复制到所有平台。
- 已存在待发任务时避免撞期；用户明确要求替换时，指出会被替换的任务。
- 发布频率没有用户约束时，可参考 `../../shared/pillar-and-cadence.md`，但把它当作默认值而非平台硬规则。

## 每个排期项必须包含

- 日期或相对日期
- 平台
- 具体选题
- 内容目标：曝光 / 互动 / 收藏 / 转化 / 社区维护等
- 形式：图文 / 卡片 / 短视频 / 长视频 / 文章等
- 一句话角度
- 所需素材或制作动作
- 状态：待选题 / 待创作 / 待审核 / 待发布
- 关联活动、热点或既有 Mother（如有）

## 工作流

### 1. 确定排期范围

确认开始/结束日期、目标平台和用户期望的产量。跨月任务按自然周展示，同时保留真实日期。

### 2. 读取已有时间线

用户要求结合已有内容时，先读取 Ripple 日历上下文，标记不可冲突的槽位。不要通过猜测标题判断是否同一内容。

### 3. 建立槽位

根据频率生成空槽位，并依次填入：硬日期内容 → 已确认选题 → 热点/活动候选 → 常规内容候选。

### 4. 做冲突检查

至少检查：

- 同平台同日是否重复发布；
- 连续三条是否主题过于相似；
- 活动内容是否晚于活动本身；
- 视频/复杂视觉是否没有制作提前量；
- 推广内容是否连续出现导致内容结构失衡。

### 5. 输出

先给总览表，再给需要提前制作的任务清单。表格至少包含：日期、平台、选题、形式、目标、状态。

用户要求落文件时，保存到当前 Mother/内容目录对应的产物位置；没有明确内容归属时，可使用 `outputs/内容日历/content-calendar-YYYY-MM.md`。

## 与其他能力的边界

- 长期支柱、受众路径和增长逻辑交给 `skill-content-strategy`。
- 批量生成候选标题交给 `skill-content-matrix`。
- 节日和营销节点查询交给 `skill-event-calendar`。
- 已发/待发的权威时间线由 `skill-content-calendar-log` 管理。
- 本 Skill 只产出计划，不绕过内容工作台的审核与真实发布确认。
