# 自然度检查清单（按需）

本文件用于用户明确要求“去 AI 感 / 更自然”，或文章确实存在明显模板化表达时做诊断。它不是平台合规门，也不要求每篇公众号文章逐条凑配额。

## 使用原则

1. **事实和用户声音优先**：不为了“真人味”编造个人经历、失败、数字、人名、时间或观点。
2. **没有固定标点/人称配额**：第一人称、问号、破折号、括号、短句都按语义与账号 voice 使用，不要求出现固定次数。
3. **词表是风险提示**：命中“首先/其次/赋能/闭环”等词时看上下文；如果是准确术语或用户习惯可保留，只有模板化、空泛时才改。
4. **改句式，不做同义词替换游戏**：发现公式化段落时重写信息组织，避免为了躲词表制造更别扭的文字。
5. **一次检查只处理可举证的问题**：同一版本已经处理过且没有新变化的维度不重复扫描。

## 检查维度

### ① 直接性与开头

- 开头是否直接进入一个具体问题、事实、场景或判断？
- 宏观背景如果确实必要可以保留；纯“随着……发展”“在……背景下”式铺垫且不提供信息时压缩。

### ② 句子节奏

- 检查是否连续多句都采用同样长度、同样三段式结构或同样转折模板。
- 长短句可以变化，但不要求“每 3-4 句强插一个 5-12 字短句”。节奏服从内容。

### ③ 套话与抽象词

常见风险词包括：`赋能 / 打造 / 聚焦 / 生态 / 闭环 / 链路 / 抓手 / 底层逻辑 / 方法论 / 一站式 / 端到端 / 降本增效 / 破局 / 沉淀`。

- 如果这些词没有给出具体对象、动作或结果，改为可观察的事实。
- 技术、商业语境中词本身准确时不要机械删除。

### ④ 观点与主体

- 文章需要作者判断时，确认判断的主体和依据清楚。
- 第一人称只能来自真实作者立场/材料；没有个人经历就不要虚构“我昨天……”“我踩过坑……”。
- 客观教程、新闻整理、学术解释可以少用或不用第一人称。

### ⑤ 事实密度与证据

- 需要事实支撑的判断应有来源、具体对象或可核实依据。
- 不设“每 500 字必须有一个数字/专有名词”的配额；没有可靠数字时宁可准确描述，也不要编数字。

### ⑥ 标点与结构

- 标点服务语义：问句真的是问题才用问号，插入语需要时才用破折号/括号。
- 不要求文章故意加入反悔句、自嘲或“扯远了”等不完美痕迹。
- 章节长度可以不对称，但应由信息量决定。

### ⑦ 账号 voice

- 有 Ripple Profile / 账号 voice：优先匹配真实账号的用词、语气、节奏和禁区。
- 没有持久画像：使用用户本次给出的参考稿/语气说明；不要回退到仓库示例账号人格。

## 完成标准

- 已解决能够指出具体文本证据的模板化问题。
- 未改变事实、品牌声音和用户明确要求。
- 剩余只是个人审美偏好时可以交付并说明建议，不循环改到某个主观分数。
