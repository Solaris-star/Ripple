# 返工流程与审核原则

## 返工流程

审核本身只产出结论。只有用户明确要求修改，或当前任务已经授权“修到可用成品”，才返工：

1. 保留原始任务、当前产物和具体失败证据，只读取受影响部分。
2. 客观缺陷（缺文件、裁切、格式错误、用户关键要求缺失）定向修复后重验相关检查项。
3. 主观风格/优化建议默认不自动返工；用户要求改风格时再处理。
4. 环境、权限、网络失败不靠重写内容解决，报告阻塞并保留已完成产物。
5. 不设“一律只返工 1 次”或“无限返工”的全局规则。只要每轮在修复明确客观缺陷且成本在授权范围内可以继续；连续尝试不再缩小问题、需要新的付费范围或约束互相冲突时停止并说明。

## 审核原则

- **宽进严出** — 大多数产物应该是 ✅ 或 ⚠️，❌ 是少数情况。
- **不追求完美** — 有小问题但整体可用就通过，不要反复返工。
- **尊重创意** — 不因为风格偏好判定不达标，只管「任务是否完成、质量是否达标」。
- **透明告知** — 无论通过还是返工，都把审核结论告诉用户。
