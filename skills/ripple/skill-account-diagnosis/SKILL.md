# 账号诊断 / 起号体检

> 对着一个**具体账号**做证据式体检并给处方。优先使用现有 Profile + 近期内容/指标；没有完整 Profile 时仍可基于可见账号内容做有限诊断，无法判断的人设/受众维度标 unknown，不强制先建画像。

## 前置条件

需要一个明确账号和至少一种可用证据：Profile、近期内容/数据、账号截图，或 Ripple 能读取的账号近期作品。证据不足只降低结论范围，不把整个诊断停掉；完全没有具体账号材料时才先补输入。

## 输入

| 项 | 必需 | 说明 |
|----|------|------|
| 画像名 | 否 | 有 Profile 时作为定位/受众基准 |
| 近期内容数据 | 推荐 | 用户提供数据，或小红书已连接账号通过 `ripple_xhs_read(operation=notes)` 读取近期作品；缺失指标保持 unknown |
| 具体困惑 | 否 | 如"播放上不去""是不是被限流了" |

## 输出

一份诊断报告 + 分阶段行动清单：

1. **五维诊断**（每维：现状 → 证据 → 结论），见 [diagnosis-framework.md](references/diagnosis-framework.md)：
   垂直度 / 定位清晰度 / 限流降权信号 / 流量池阶段 / 内容-受众匹配。
2. **病因→证据→处方**：每个问题都要三段式，不给空泛建议。
3. **分阶段起号意见**：按当前所处阶段（0-500 / 500-5k / 5k-1w / 1w+）给这一档该做什么。
4. **发布建议**：内容方向优先级、发布节奏、需要补强的能力（可指向下游 SKILL：选题→content-matrix、脚本→video-script、合规→quality-gate 等）。
5. **信息缺口**：把会影响判断的缺失数据列出来；先交付现有证据能支持的诊断，只有关键决策必须依赖缺失信息时才追问。

## 执行步骤

1. **读取必要基准**：有 Profile 时只读当前诊断需要的定位、受众、平台和偏好字段；无 Profile 不因此停止。
2. **收集近期数据**：小红书已连接账号优先按需读取近期作品；其他平台使用用户给出的数据/截图。数据不完整时标注范围，不补 0。
3. **逐维诊断**：按 diagnosis-framework.md 的标尺给每一维打现状 + 找证据 + 下结论。限流信号按清单逐项自检。
4. **判定流量池阶段**：结合粉丝量级 + 近期互动率，定位当前档位。
5. **开处方**：把诊断出的问题按"病因→证据→处方"组织，处方要具体可执行（不是"多互动"这种废话）。
6. **给分阶段动作清单**：当前档 + 下一档的关键动作。
7. **列信息缺口**：说明哪些结论当前只能初步判断，以及最有价值的下一项数据；不为了补齐模板把所有缺口都变成阻塞问题。
8. **回流建议**：诊断中发现的可复用洞察，建议用户确认后写入 `profiles/<名>/memory.md`（本 SKILL 不自动改 Profile，只建议）。

## Profile 感知

- **有 Profile**：全程以该画像的定位/风格/受众/红线为基准做诊断——垂直度是"离该定位有多远"，而非通用标准。
- **Profile 不完整/缺失**：只诊断当前证据覆盖的内容表现、方向和可见风险；人设/受众一致性缺少基准时标 unknown，可建议后续完善 Profile。
- 诊断结论只**建议**回写 memory，由用户确认，避免污染画像。
