# 小红书分析

本 Skill 的首选数据入口是 Ripple 受控工具 `ripple_xhs_read`。它使用 Ripple 中已连接的小红书账号和账号独立浏览器 Profile；Skill 不读取 Cookie、xsec token、浏览器目录或其他凭据。

## 数据入口

按任务选择最小读取范围：

| 需求 | `ripple_xhs_read.operation` | 说明 |
|---|---|---|
| 有哪些已连接账号 | `accounts` | 只返回账号 ID、标签与脱敏身份 |
| 看当前推荐内容 | `feed` | 个性化推荐流样本，只代表所选账号本次可见内容 |
| 搜一个主题 | `search` | 关键词搜索样本 |
| 看自己的近期作品 | `notes` | 创作者作品列表与可见指标 |
| 深挖一篇 | `note` | 标题、正文、作者、可见指标等 |
| 看评论/需求 | `comments` | 指定笔记的评论样本 |

用户已经给出足够的文本、截图或此前读取结果时直接分析，不为了“完整流程”重复联网读取。

## 核心边界

- **推荐流 ≠ 全平台热榜**：必须写明 `sample_scope` 和采集时间；只能描述“本账号本次样本中观察到”。
- **可见指标缺失就是未知**：没有 views/collects 等字段时不补 0，也不反推精确曝光或粉丝增长。
- **相关性 ≠ 因果**：标题、封面、结构与高互动同时出现，只能先形成待验证假设；跨多条/多期重复出现后再提高信心。
- **平台风控不绕过**：验证码、NeedVerify、登录失效、访问限制时停止受影响的读取分支，保留已有样本继续做有限分析。
- **本 Skill 只读**：评论发送/删除只能创建互动草稿并由 Ripple「互动管理」确认；真实发布走「发布工作台」。

## 分析模式

### A. 推荐流 / 搜索样本

1. 记录来源、关键词或推荐流范围、采样时间和样本量。
2. 对标题钩子、主题、内容形态、作者/视觉线索、可见互动做聚类。
3. 区分：`观察事实` / `可能解释` / `下一步验证`。
4. 用户要选题时，把 3–5 个最有证据的机会交给现有选题流程；用户只要 3 个就只给 3 个，不强制完整矩阵。

### B. 单篇笔记拆解

1. 读取 note；只有评论确实影响判断时再读 comments。
2. 拆标题、开头、信息结构、视觉/素材线索、互动信号。
3. 提炼可迁移的方法，不复制作者个人经历、专有表达或原图。
4. 给出适合当前账号的原创角度，并注明哪些判断仍需更多数据验证。

### C. 账号近期作品

1. 读 `notes`；需要定位/受众基准时按需读取当前 Profile。
2. 用账号自身近期样本做相对比较，避免跨粉丝量级直接比绝对互动。
3. 输出：内容方向分布、相对表现较好的作品、可测试模式、短板、下一批实验选题、数据缺口。
4. 没有完整 Profile 也可以做“内容表现诊断”；无法判断的人设/受众维度标 unknown。

### D. 评论洞察

读取 `comments` 后可交给 `skill-comment-insights` 做量化情绪/诉求分析，或 `skill-community-ops` 生成回复策略与选题。需要实际回复时再由 `skill-xhs-comment-reply` 创建待确认互动草稿。

## 完成标准

- 能说明数据来自哪里、样本范围和时间。
- 事实与推测分开；缺失指标不补造。
- 用户要求的分析/选题已经完成，不因为还有可选数据就无限抓取。
- 读取受阻时明确是部分完成还是阻塞，并保留已经取得的合法数据。
