# 小红书读取技术参考

本文件描述 Ripple 托管读取的行为边界，不要求 Agent 接触 Cookie、xsec token 或浏览器目录。

## 数据定位

小红书部分笔记链接包含短期定位参数。Ripple 读取推荐流、搜索或作品列表时，会把完整定位信息留在**所选账号的私有目录**；返回给前端/Agent 的 URL 会去掉 query。后续读取详情/评论优先使用 `note_id`，由后端取回私有定位信息。

用户直接提供完整小红书笔记链接也可以作为一次性定位输入，但不要在报告、日志或选题库里回显其中的临时 token。

## 可见指标

常见字段可能包括 views / likes / collects / comments / shares，但不同页面并不保证全部出现。规则：

- 缺字段 → `null/unknown`，不补 0。
- `1.5万` 等显示值可换算为整数，但要保留“页面可见值”的证据语境。
- 没有曝光量时不要计算依赖曝光的互动率。
- 推荐流/搜索卡片的数字和创作者后台数据不一定是同一口径，不能直接混算。

## 错误状态

| 状态 | 处理 |
|---|---|
| 登录失效 | 暂停需要该账号的读取，提示用户通过 Ripple「账号与平台」重新连接 |
| 验证码 / NeedVerify / 风控页 | 停止受影响远端分支，不自动穿过验证；已有样本继续离线分析 |
| 账号浏览器正在发布/互动 | 返回账号忙，稍后重试；不另开第二个 Profile 抢状态 |
| 页面结构变化 | 返回读取失败/空字段，不能把空数据当真实 0 |
| 单篇定位过期 | 从正常推荐流、搜索或账号作品入口重新取得该笔记定位，再继续 |

## 推荐流语义

`feed` 是**所选账号当时的个性化首页样本**。它适合回答“这个账号现在被推荐什么”“当前样本有哪些内容形态”，不适合直接回答“全平台最热是什么”。全平台热点继续使用 Ripple「热点雷达」的热搜来源。

## 搜索语义

`search` 返回当前关键词下的可见样本。排名是本次搜索页面的结果顺序，不把它解释为精确搜索量或官方热度分。需要比较多个关键词时控制样本数量，并在报告中记录各自采样范围。

## 评论与互动

只读评论返回稳定字段 `id / nickname / content / time / like / parent`。真实回复/删除时优先用评论 ID，同时保留昵称与原评论片段辅助核对；无法唯一定位就不发送。

Ripple 托管写操作遵循：

`互动草稿 → 用户在互动管理确认 → 持久化执行意图 → 平台操作 → verified / partial / unknown_result / not_submitted`

`unknown_result` 不能自动重发，必须先核对结果。

## 完成标准

分析报告至少能说明：数据来源、采样范围、时间、已取得字段、缺失字段。任何“爆款规律/限流/算法偏好”都应给出证据强度，不把不可见内部平台字段当作已知事实。
