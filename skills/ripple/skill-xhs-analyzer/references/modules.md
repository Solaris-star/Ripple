# 小红书分析模块

这些模块是分析视角，不是每次必跑的流水线。先完成用户当前问题，再按需要组合。

## A. 推荐流样本

输入：`ripple_xhs_read(operation=feed)` 的当前账号个性化推荐样本。

输出：主题、标题和内容形态聚类，并明确 `sample_scope`。不能把它命名为“小红书全站热门”。

## B. 关键词机会扫描

输入：一个或少量明确关键词，通过 `operation=search` 获取样本。

观察常见子主题、标题表达、内容形态和可见互动结构。用户只要少量选题时直接输出指定数量；需要系统内容规划时再交给 `skill-content-matrix`。

## C. 单篇结构拆解

输入：`operation=note`；只有评论确实影响判断时再用 `comments`。

输出：标题 Hook、开头、结构、素材/视觉线索、互动证据、可迁移方法、作者专属不可迁移部分和待验证假设。

## D. 账号作品诊断

输入：`operation=notes` 的近期作品，可选 Profile。

重点做账号内相对比较：主题分布、相对高表现内容、重复出现的结构、异常低表现和数据缺口。没有 Profile 时仍可分析内容表现，不做人设一致性强结论。

## E. 内容形态比较

当同一关键词下确实有足够图文/视频样本时，比较主题、表达方式和可见互动。样本少时只写观察，不把小样本平均值包装成稳定平台规律。

## F. 评论需求洞察

输入：评论样本。可交给 `skill-comment-insights` 做聚类/量化，识别重复问题、购买意图、争议、许愿和误解。需要回复时交给 `skill-community-ops` 拟稿，再由 `skill-xhs-comment-reply` 建立待确认互动任务。

## G. 选题机会

综合 B/D/F 的证据生成选题。每条写清对应样本信号、适合当前账号的原因、建议内容形态和需要验证的假设。已有选题库时去重，不另建一套 topic 数据库。

## H. 模式验证

一次高表现只形成候选假设。跨多条/多批数据重复出现，且没有明显热点、发布时间或账号体量等替代解释时，才提高可信度。真正发布后的结果交给 `skill-content-postmortem` 复盘。

## 组合建议

- “看一下推荐流有什么机会” → A → G
- “搜这个关键词给我 3 个选题” → B → G
- “这条为什么好” → C
- “这个账号最近怎么了” → D
- “看看评论大家在问什么” → F
- “找到能复用的打法” → C/D/F → H → G

完成当前目标后停止，不为了跑满模块继续远端读取。
