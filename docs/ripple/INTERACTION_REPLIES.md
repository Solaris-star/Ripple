# 小红书与 X 评论回复

本轮范围是 Windows 本地执行设备、当前账号作品下的评论。每次最多读取 30 个作品，单作品最多读取 100 条评论，页面显示当前读取数量及样本范围。没有实现全量历史抓取、私信、无人值守回复、X 官方 API 互动或远程 Browser Node 传输。

## 操作与结果

单条和批量回复都先保存草稿，再在应用确认框中显示账号、目标评论和保存后的完整回复。保存失败或版本变化时不发送。每批最多 20 条，卡片、评论详情和任务详情使用相同的回复编辑状态。AI 返回时只应用仍未被手工修改的建议；手工流程不依赖 AI。

主导航提供“互动”入口。选择账号后，评论数量、草稿和历史都按该账号筛选；平台按钮和“全部账号”页显示跨账号汇总。切换作品会立即清除旧选择并加载对应缓存，迟到的读取响应不会覆盖新作品。刷新后恢复上次账号和作品，可直接刷新当前作品的评论。

回复编辑内容自动保存在当前浏览器，并沿用登录用户和 Workspace 的存储范围；每个账号作品来源与评论 ID 分别保存。界面区分“编辑内容已保存在此浏览器”和“已保存待发送草稿”。浏览器存储失败时显示未保存，并在离开前提醒；仍可手动保存服务端草稿。取消任务、放弃本地修改和发送完成会清理对应本地编辑。“删除平台评论…”放在“更多操作”中，和放弃回复草稿分开，最终确认页写明删除对象和不可恢复的后果。

执行记录逐条保留 `pending`、`submitting`、`verified`、`not_submitted` 或 `unknown_result`。最终提交前先写入记录，单个 Worker 使用独占创建的 `submission.json` 防止再次点击。批量遇到未知结果、登录失效或平台验证时停止，尚未开始的条目标为确认未发送。

重复执行只返回原任务。未知结果须按评论逐条人工核对；只有确认未发送项可建立重试草稿。重试复制原任务保存的目标与内容，不依赖仍在当前评论样本中，也不会重建已发送项。已执行记录不会因达到任务数量上限而自动删除，避免失去防重复依据。

建立重试草稿时会查询同账号、同作品的后续执行记录，排除已经成功、正在执行或仍待核对的条目。原批次继续保留当时的逐条结果，页面另外显示当前可重试数量及已有记录入口。顶层评论按同一重试链检查，删除按评论 ID 检查。账号存在执行中或待核对操作时，草稿页提前显示原因并提供处理入口；可以保存修改，发送预览暂不可用。

旧草稿和历史继续可读。历史记录缺少逐条证据时显示待核对，不依据旧的整批成功标志推断已发送。

## 平台行为

小红书读取和回复复用原 `XiaohongshuProfile`，在后台运行。发送前核对当前账号、作品作者与唯一评论 ID。只有请求目标、发送账号、回复 ID 和内容均匹配的回执才算成功；输入框或页面上出现相同文字不算证据。发送点击报错后不再尝试快捷键或其他提交按钮。

旧小红书连接可能没有保存远端账号 ID。互动能力会提前标为“需要重新校验”，可在互动页点击“校验此账号”，后台检查完成后更新原页面；不会自行打开登录窗口。平台要求重新登录时仍由用户主动处理。

X 复用 `x-browser` 的独立登录 Profile。读取页面自身的响应，以真实 Post ID 保存作品、回复及父级关系，不主动调用 X 官方 API。不能确认属于当前账号作品的条目不发送。首版只发送纯文字回复。

账号能力按连接方式与执行设备返回。本地 `x-browser` 可用；`x-api`、远程节点及未连接账号会返回具体原因。浏览器模式保留实验性说明：X 明确限制非 API 网页自动化，并提示可能永久封禁账号。参见 [X 自动化规则](https://help.x.com/en/rules-and-policies/x-automation)。

## 字符计数

标准帖上限为 280 加权字符，使用 NFC，URL 计为 23，中文通常计为 2，Emoji 序列计为 2。URL 识别使用固定版本的 `twitter-text` 和对应 Python 移植。两种语言库自带的 Emoji 表不同，因此前后端统一读取 `ripple/data/x_emoji_sequences.json`，包含固定 Unicode 17.0 的 5,225 条记录和 v3 权重配置。普通文本形式的 `©`、`®` 保持权重 1。

计数只处理副本，保存与发送保留原文。测试覆盖全部共享 Emoji、紧邻 URL、中文、组合 Emoji、NFC、换行及 280 边界。长 URL 不再因旧的 1,000 原始字符限制而被误拒绝。

超过 280 加权字符的回复可以保存草稿，预览发送按钮保持禁用并提示需要减少的数量。服务端在发送前再次检查；超限或依赖缺失时不会建立执行快照或增加发送次数。

规则来源：[X 字符计数说明](https://docs.x.com/fundamentals/counting-characters)、[twitter-text](https://github.com/twitter/twitter-text)、[Unicode 17.0 Emoji 数据](https://www.unicode.org/Public/17.0.0/emoji/emoji-test.txt)。数据许可证保存在 `LICENSES/Unicode-3.0.txt`，可用 `scripts/update_x_emoji_data.py` 从固定版本重新生成。

Python 的 URL 解析代码位于 `ripple/_twitter_text/`，由 `twitter-text-parser==3.0.0` 的相关模块改编，许可证见 `LICENSES/twitter-text-parser-MIT.txt`。前端依赖固定为 `twitter-text@3.1.0`。运行时不联网获取字符规则。

能力接口区分账号未连接、身份待校验、连接方式不支持及依赖缺失。响应包含 `schema_version: 2` 和 `restart_required`；前端遇到旧接口或运行中被更新的互动模块时提示重启服务。本机上层 `Start-Ripple.ps1` 启动检查也包含 X 字符计数依赖。

人工核对与放弃草稿使用页面内确认框。任务详情保留作品标题、评论原文及核对入口；X 直接打开目标评论，小红书打开所属作品。刷新本地回执仍不等于向平台重新查询。

## 接口兼容

所有接口仍在 `/api/ripple/interactions` 下。

| 操作 | 请求内容 |
| --- | --- |
| `POST /{id}/execute` | `confirmed: true`、保存响应中的 `expected_updated_at` |
| `POST /{id}/resolve-unknown` | `item_id`、`result: verified/not_submitted`、`confirmed: true`、当前 `expected_updated_at`、可选 `note` |
| `POST /{id}/retry-draft` | 当前 `expected_updated_at`、仅包含确认未发送条目的 `item_ids` |
| `POST /{id}/refresh-result` | 只读取本地逐条 Worker 回执，不重新发送 |

旧 `/api/ripple/xiaohongshu/interactions/{id}/execute` 同样要求 `expected_updated_at`。缺失返回 422 并提示刷新，版本冲突返回 409。执行核对版本与锁定快照在同一事务中完成。响应中的 `item_results` 保存逐条证据和人工核对信息。

## 平台稿

主稿更新只显示提示。选择“保留平台稿继续发布”会保留平台改写及原来源版本。同步窗口展示标题、正文、话题和素材差异，默认不勾选，只修改所选字段。保存前可撤销本次同步，其他字段的后续编辑保留。发布任务仍使用既有版本检查、定时状态及未知结果防重复检查。

## 验证范围

`tests/test_interaction_safety.py` 覆盖保存版本、并发点击、逐条持久化、超时、重启、历史兼容和重试限制。`tests/test_x_interactions.py` 覆盖账号能力、归属检查及计数。原有互动、Worker、发布与平台版本相关测试继续执行。

`tests/test_browser_reply_adapters.py` 使用真实无头浏览器和页面替身，拦截所有平台网络请求，验证一次点击、有效回执、无回执、点击超时、错误账号、错误目标和登录失效。`tests/test_interaction_ui.py` 使用隔离服务数据与实际 React 组件，覆盖确认稿、保存失败、版本冲突、选择数量、AI 延迟、空页面、账号隔离和选择同步。

Windows 默认使用已安装的 Edge；可用 `RIPPLE_TEST_BROWSER` 指定其他 Playwright channel。`RIPPLE_QA_ARTIFACTS` 可指定隔离页面截图目录。自动测试使用隔离数据和平台替身，不发送真实评论。

2026-09-26 在用户明确授权下，通过 Codex 侧边浏览器和当前小红书适配器完成单账号真实验收：发布 1 条测试评论、回复 1 条，分别取得平台回执；重新读取后确认 2 条内容存在，再依次删除回复和顶层评论，最终重新读取为 0 条。验证中修复了作品卡片重复、本人主页新链接格式、展示链接覆盖完整定位链接、折叠评论框，以及同名父子评论删除定位问题。完整定位链接仅保存在账号私有目录，页面仍使用无访问参数的展示链接。顶层评论提交记录与回复相同，提交前落盘，回执必须绑定账号、作品及完整文本。

该验收只覆盖本机已连接的小红书账号，不代表 X 或其他平台已完成真实写入验证。平台页面或回执格式变化时停止或显示待核对，不依据输入框中的文字报告成功。
