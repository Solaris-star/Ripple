## 1. Goal / Non-goals

目标：使用户围绕实际运营账号开展选题、内容、发布和复盘；每个账号可有独立的内容画像，也可与同方向账号共享基础画像。支持先确定定位再绑定、先绑定再从既有内容生成画像建议两条路径。收拢设置、统一导航命名，同时消除上下文错绑和内容串号风险。

核心用户路径：
- 新起号：创建画像 → 确认定位 → 选择拟运营平台 → 可选绑定真实账号 → 按画像选题/制作 → 明确账号后发布。
- 已有号：绑定并核验身份 → 选择已有画像 / 手工建档 / 分析历史内容 → 审阅画像建议 → 确认关联 → 按账号工作。

成功边界：账号身份、内容策略和执行能力分开建模，并在使用时显式解析为一个可见、可追溯的工作上下文。界面隐藏低频复杂设置，安全检查和排障能力保留。

非目标：本轮不引入企业级品牌/部门/项目/组织四级嵌套；不替换已有发布系统；不直接迁移所有业务到同一数据库；不绕过平台权限抓历史内容；不推断真实粉丝人口结构；不让Agent自动批准画像、扩展权限或发布；不在仅讨论阶段开启真实分析。

## 2. Success criteria（可验证）

1. 同一个人管理的小红书科技号与小红书生活号可关联不同画像；抖音科技号可与小红书科技号共享基础画像但独立设置口吻/栏目/形式。
2. 一个账号在同一工作空间里只存在一个当前生效的主画像关系；允许暂未关联。多个账号可以关联同一基础画像。无绑定画像仍能策划；未关联账号仍能管理连接、手动制作，不被迫重新扫码。
3. 内容画像使用独立稳定ID，与账号ID、浏览器Profile、Agent配置、登录用户/Workspace明确区分；显示名称变化不导致关联、策略、历史任务断裂。
4. 先画像后绑定、先绑定后画像、导入材料建画像、复制已有画像等流程汇合到同一个数据模型，不产生两套资料。
5. 账号分析先核验本人账号身份及采集能力，只读允许的自有内容；展示时间窗、样本条数、正文/标题/字幕等覆盖情况、费用和模型。获取失败或信息不足时不得假装完成。
6. Agent画像输出为提案，逐字段提供来源与样本范围。历史观察、AI推测、用户希望的新方向分别呈现；只有人工确认的版本供后续任务使用。
7. 人工字段、红线和已锁定内容不会被后台分析覆盖。重新分析后可以逐项应用；并发编辑使用expected_revision检测冲突。
8. 选择具体账号能解析出对应画像，运行中的对话/选题/发布任务固定提交时的上下文。切换左上角范围不改写已有会话或发布目标。
9. 同平台两个账号可有两份账号版本；版本去重不再只用platform。发布审核固定account_id、profile_revision、connection/auth_revision及内容版本；任何目标改变必须重新核验，不能自动换号。
10. 选题/活动规则核验和自动发现使用同一账号范围解析器。登录可见性、身份认证、参与资格、发文能力、历史内容读取能力分开显示与校验。
11. 画像改动能够显示影响的账号数、未执行任务/策略，并只在用户确认后作用于后续任务。历史策划和已发布记录保留原快照；重大定位/范围变更使自动策略进入待复核，不自动扩张付费调用。
12. 主导航为首页/选题/内容/发布/素材/技能/设置；账号管理统一进入设置→账号。所有原链接、首页快捷操作、错误提示跳转、浏览器刷新/返回均能到正确子页。
13. 本机模式不显示“用户与访问”空说明页；Server仍执行登录、Workspace、角色与发布授权，管理入口按权限显示为“成员”。删除“高级设置”分类后，运行环境与设备排障仍可从Agent及账号故障处到达。
14. MCP页只负责MCP连接与能力状态；技能/插件能力入口归技能页。不能把保存手工配置当真实连接成功；本轮至少梳理状态和归属，完整MCP传输实现另定范围。
15. 修改画像离开时不丢未保存内容；新任务可显示实际生效画像及版本；全部账号模式只用于汇总，不暗含对全部账号生成/发布的授权。
16. 迁移保留账号登录态、现有画像全文及自定义Markdown、旧ID/标签/计划/任务，不凭名称猜归属；无法确定的项进入待关联清单。验证无真实模型消费、无发布、无平台账号退出。

### 本方案补全/默认建议

- “用户画像”统一对外称“账号画像”或页面内简写“画像”，描述内容定位与表达策略，不描述登录Ripple的自然人。
- 首版采用一画像对多账号、每账号一主画像，加少量账号级差异；差异大时独立创建/复制画像。
- 同方向账号可以共享，跨品牌或完全不同赛道默认独立。用户没有明确选择时绝不自动合并。
- 初次建档只要求名称、方向、目标受众、拟运营平台和必要红线；现有六维完整内容仍可编辑，不必初次填完。

- 历史内容分析默认建议最近90天、最多30条，经用户调整后执行；这是本方案的预算建议，不是平台能力承诺。

## 5. 概念模型与关系

### 对用户只暴露三个概念

- 画像：账号准备做什么、面向谁、表达方式与红线。
- 账号：实际平台上的具体身份，带平台昵称/账号标识/连接与能力状态。
- 当前范围：本次浏览/选题/创作针对哪个画像及其哪些账号，可选择全局汇总或未绑定规划。

后台保留但不要混称“画像”的实体：登录用户及Workspace权限、独立浏览器会话、Agent运行配置。

### 推荐关系

Workspace（权限边界）
  ├─ 账号画像：科技工具
  │    ├─ 小红书科技号：继承基础画像，账号差异为教程图文/收藏清单
  │    ├─ 抖音科技号：继承基础画像，账号差异为录屏/短视频开头
  │    └─ 公众号科技号：继承基础画像，账号差异为完整长文/引用密度
  ├─ 账号画像：城市生活
  │    └─ 小红书生活号：独立定位与表达
  └─ 已连接但待关联画像的账号

上述账号均为设计示例，不代表当前真实绑定情况。

一个画像可以无账号，作为起号规划。每个账号当前有零或一个主画像，绑定关系包含自己确认的差异与版本。共有基础修改显示影响范围；差异较大时复制出独立画像，复制后默认不继续联动。

不采用首版任意多对多：一个账号同时跟随多个画像容易让推荐、记忆、默认口吻和预算归属含混。偶发跨方向内容用本次策划设置，重大转型通过新版本/新画像明确切换。

### 生效规则

硬性限制（平台规则、活动规则、Workspace安全规则、用户明确禁区）必须同时满足，不能被口吻配置覆盖。

软性偏好在授权范围内按本次任务明确要求→账号级差异→基础画像→默认建议处理；使用哪一级显示来源。用户锁定的具体策划字段保留，改变它必须主动解锁/应用建议。

账号事实（昵称、平台ID、已验证能力）来自连接验证；未来受众和选题方向是用户决定；AI从历史内容得到的主题/风格为观察或建议，三者分开存储。

## 6. 两条建档路径

### 路径A：先建画像再绑定

设置→账号→画像→新建画像。
第一屏填写名称、方向、受众，选择拟运营平台；可使用模板或已有画像副本。可选补充风格、栏目、禁区、制作能力；无需触发模型即可保存人工基线。

确认后提供“绑定平台账号”和“先去找选题”。先策划完全可行；没有真实账号时显示“尚未绑定”，自动发现只读取公共资料与已授权范围，发布按钮解释缺失条件。

绑定时从当前画像带入拟关联对象，完成OAuth/扫码/凭据验证后显示平台头像、昵称、可靠远端ID和待关联画像，用户最后确认；不凭同名自动认定自己绑定了正确账号。

账号连接失败保留画像；画像保存失败保留已建立连接且标“待关联”，不撤销用户登录态。

### 路径B：先绑定再由Agent建画像

设置→账号→添加账号→选择平台及平台支持的连接方式→确认真实账号身份。

绑定完成后选“关联已有画像”“Agent分析账号”“手动填写”“稍后处理”。分析入口先列能力：可读主页/可读历史正文/仅标题/字幕可用/暂不支持。连接成功不表示有历史内容读取权限。

用户确认分析范围、时间窗和样本数量、执行设备、Runtime/模型与费用；仅读取该账号有权访问的自有公开/已发布材料，不默认采集私信、粉丝个人资料、评论者档案或个人常用浏览器数据。

后台步骤：账号身份再次核验→有界只读采样→去重/标记转载/商业稿/过往赛道→用户可剔除不代表当前方向的样本→Agent分析→结构化建议与出处→用户确认基础画像与该账号差异。

分析结果例：
- 观察：可读样本中主要为工具教程，列出证据作品与日期。
- 推断：内容可能主要帮助办公效率需求者，标“待确认”；不能从标题推断真实粉丝年龄或地域。
- 用户意图：希望未来转向开发者工具，该意图由用户确认，不由历史自动否决。
- 待补：仅有标题时不能断言完整叙事结构、语气和视频节奏。

失败/新号：提供粘贴作品、导入用户导出的内容、手工填写。未支持历史读取的平台使用同一分析契约但清晰禁用自动取样。首版推荐先核实并适配用户当前重点使用的小红书/抖音的只读内容能力，再按能力登记逐平台扩展；不承诺一次实现所有平台全量历史采集。

重新分析只生成新的草案，不替换当前生效版；比较“当前值/建议值/来源”，可逐项应用。样本进入模型前去除凭据、无关个人信息和内部路径；外部内容当资料处理，不能执行里面的指令。

| 素材 | 默认当前画像/账号范围；可标记Workspace共享素材，但其他画像的素材不自动作为训练样本 |
| 技能 | 展示适用能力和授权范围，不存另一份独立业务画像 |
| 设置 | 管理所有授权账号/画像，带当前范围提示；平台连接、模型配置、内容策略各有唯一入口 |

运行任务在提交时固定workspace_id、content_profile_id/revision、account_id(s)、binding_revision、source_refs、model选择；换浏览范围不改任务。请求返回绑定原范围，不能迟到覆盖新账号页面。

老对话固定原画像；切换范围后继续旧对话时提示“此对话属于X”，提供切回或创建新会话。重命名画像仅改变显示名称；历史记录保留原版本显示与稳定ID。

### 设置→账号

账号页内部以“已绑定 / 画像 / 待处理”为视图，而不再让所有未绑定平台卡片占满首屏。主要操作始终是“添加账号”和“新建画像”。平台目录放到添加弹窗。

账号列表每行显示：头像+平台+账号名称；关联画像；连接状态；内容读取能力；画像状态；操作。示例状态组合“连接正常｜画像待确认”或“需重新登录｜画像V3有效”，不可合并成一个绿色已连接。

详情内用“概览 / 画像 / 样本 / 连接”组织。这里的连接含该账号登录/授权范围和诊断，避免与MCP外部工具连接混淆。

画像视图显示关联账号数和使用情况；点击进入可编辑结构化页面，六维信息可组织为“定位/受众/风格/运营/边界/经验”六组，保留原文视图和自定义Markdown。顶部显式“保存草稿”“确认生效”，状态含未保存/草稿/已生效，返回前提供离开确认。用户对纯手工明确修改可以直接确认，不强制模型润色。

### 用户与访问

本机版从设置导航移除，此页的“本机免登录”摘要可放关于→运行信息，不占一级子分类。

Server版需要保留真实成员和登录授权管理；可显示“成员”，权限不足者不显示管理操作，退出登录在用户菜单可到达。对应后端权限、CSRF、会话和Workspace隔离继续生效。隐藏菜单不代表隐藏资源可被直接API访问。

### 高级设置

删除“高级设置”分类。
- 执行节点/浏览器与本地环境→Agent→运行环境/设备（低频区域折叠）。
- 某账号缺浏览器、设备离线→账号详情“连接”直接提供精确诊断入口。
- 版本、部署模式、健康摘要与诊断导出→关于。

诊断显示去敏信息，版本读取失败时显示未知/重试，不使用静态版本号冒充真实运行版本。

### 技能、MCP、Agent、模型

- 技能：任务方法、模板、领域能力与插件提供的技能；需连接时深链到相应MCP/账号。
- MCP：外部工具服务连接、测试状态、可用工具、权限。手动填写工具ID只能叫声明，不能宣称已发现/可执行，也不能将全部未知工具自动认定read。
- Agent：使用哪个Runtime、运行状态、适配与设备/执行参数。
- 模型：哪些任务继承Agent模型、哪些使用独立文本/图像/视频模型，显示实际生效来源。避免用户修改一个模型却被另一默认配置覆盖。

本轮做职责拆分与所需状态/路由；完整外部MCP协议或运行器架构替换不混入本任务。

## 9. 工程设计与一致性

### 稳定标识

建议字段：workspace_id、content_profile_id、profile_revision、account_id、binding_revision、connection/auth_revision、agent_profile_id。

现有accounts.profile_id属于浏览器Profile，保留兼容或逐步改别名为browser_profile_id；绝不直接复用。新接口禁止用昵称作为跨系统关联键。

### 领域数据

建议独立轻量画像域SQLite（暂名outputs/_profiles/profiles.sqlite3），只负责：
1. content_profiles：稳定ID、显示名、Workspace、当前生效revision、归档状态。
2. profile_revisions：结构化字段、原始自由文本/自定义内容、来源、状态、不可变确认版本。
3. account_profile_bindings：workspace_id+target_kind+account_id唯一，当前画像ID、账号差异、binding_revision。target_kind兼容native/social账户和BlogConnector等已有发布目标。
4. profile_analysis_runs：具体账号、授权/身份版本、样本manifest与覆盖、进度、模型、预算/usage、建议revision、失败/取消/结果未知。

账号凭据和浏览器数据保持当前私有存储，画像域只保存引用，模型不接触密钥。与既有JSON/选题SQLite的跨存储关系由服务端解析与幂等对账保证，不能承诺不存在的跨库事务。

画像确认成为唯一权威入口；profiles/<legacy-name>六维Markdown通过受控导出兼容既有Agent/skill读取。旧文件原文与额外文件必须完整保留，不能因表单字段不足丢失。外部手改文件检测后作为待导入草案；不得同时让Markdown和SQLite双向静默写入。

首阶段可先引入稳定ID注册及版本封装，再逐步实现结构化存储；最终单一权威入口是验收要求，不长期维持两个互相覆盖的版本。

### 有效画像解析

统一ProfileContextResolver供手动选题、自动发现、内容助理、活动资格、版本创建和发布审核调用。它校验Workspace授权、账号关系、画像状态、账号差异、任务快照；返回有效策略、字段来源与约束，供UI展示。

按账号生成后的版本唯一性以明确的目标账号识别，不只按平台。平台待绑定规划保留独立的planning_target标识，不伪造已连接account_id。账号断连只改变执行能力；画像仍可用于离线策划。

### 配置变更影响

确认基础画像前列出影响：关联账号、尚未执行的生成任务、主动策略、未确认策划。已运行任务保留旧快照或由用户取消，不中途混入新画像。账号转移画像属于独立动作，需要显示待发布任务并重新校验；已发布记录不迁改。

账号断连、解绑、移除画像关联、归档画像、删除账号分别定义。账号重连核验remote identity；身份改变则停止该身份的任务并要求重新确认，不能把原画像直接继承给另一个账号。删除被引用画像优先归档，必要时阻止并说明引用，不级联删除稿件。

缓存键至少包括Workspace、content_profile_id/revision、account_id/binding_revision、查询参数。左右切换时取消失效请求，旧结果不得覆盖新范围。设置懒加载当前子页，账号列表不能等完整Agent环境探测才能出现。

### 路由与命名

建立集中navigation registry，包含稳定route ID、短标签、标题、父级、权限/模式条件、别名。内部page keys/API路径不用因为中文改名而重命名。

保留旧? page=profile/accounts/channels等入口，兼容到设置→账号正确视图；保存section、view、profile_id、account_id到URL，支持刷新、分享链接、浏览器返回。所有“连接账号”“编辑画像”“修复环境”等入口用同一注册表，避免打开新建向导或设置默认Agent页。

## 10. Options considered → 推荐

A. 仅改导航名称、在账号上加一个画像下拉：最快，但同平台多账号版本、已有会话上下文、历史来源、删除/改名和主动发现仍可串号；不作为完成方案。

B. 每账号一份完全复制画像：理解容易，跨平台同品牌需要重复维护；适合不同赛道，不宜作为唯一结构。

C. 共享基础画像＋每账号一主关联及少量差异＋统一上下文解析：推荐。复用同方向配置，同时支持账号独立性；初期不开放任意多对多和多层品牌继承。

D. 引入多Workspace/品牌/项目等企业层级：权限足够复杂时再考虑。当前Workspace继续担任安全边界，画像与账号范围不取代它。

## 13. Risks / rollbacks

- 现有画像是自由文本且可能有外部文件修改：完整备份、原文保留、单一确认入口、受控兼容导出与冲突提示。
- 账号关联错误会导致内容错号：可靠远端身份核验、明确关联确认、发布前固定账号再核验，改名不改ID。
- 采样平台能力/费用不一致：逐平台探测，能力不足明示；导入材料路径先可用，不承诺所有平台无成本可取。
- 样本偏差和历史转型：时间窗/样本透明，历史观察与未来意图分开，用户可排除广告或早期非典型作品。
- 多存储迁移会破坏引用：预览迁移、幂等映射、版本校验、未确定归属不猜，跨存储任务使用对账恢复。
- 过度简化设置会损坏安全/排障：去掉无意义分类但保留条件化入口与后端检查；Server角色测试必须保留。
- 画像升级自动扩大后台范围：关联与自动策略授权分开，新关联默认只提示，重大变更待人工复核。
- 现有工作区41条变更：执行前保存精确baseline，各共享文件按本任务hunk提交/回滚；不全量git add或硬重置。
